辅导课程管理系统设计

需求梳理、数据模型、流程与实现建议

1. 项目目标

为辅导课业务搭建一套独立的课时充值与上课消课管理系统，支持销售、销售主管、派单助理、助教老师、Linda、教务老师等多角色协作，并与财务系统联动：充值同步收入，上课自动产生财务支出待办，支出确认后上课明细锁定。

2. 角色与权限

角色可见范围主要权限备注
销售 Sales辅导系统全部内容只读可查看客户课时与上课明细
销售主管 Sales Manager辅导系统全部内容只读用于监督与报表
派单助理 Dispatcher辅导系统全部内容只读在派单系统里默认隐藏辅导订单
助教老师 Tutor辅导系统全部内容编辑可新增/修改未锁定的上课与充值记录
Linda辅导系统全部内容编辑与助教老师同级管理员
教务老师 Academic Affairs仅 Order Type = 辅导 的订单登记/编辑辅导订单信息Writer、客户、Sales 数据共用
财务 Finance财务系统待办与确认结果确认/驳回支出确认后回写上课明细为锁定状态
系统管理员 Admin全部数据、用户、权限说明用户 CRUD、辅导数据管理、查看权限矩阵用户名 Admin，独立密码登录；最高权限

2.1 辅导系统 vs 派单系统权限说明

  • 辅导系统：面向 Tutor、Linda、销售、销售主管、派单助理、教务老师，展示辅导订单与课时明细。
  • 派单系统：默认订单列表中隐藏 order_type = tutoring 的订单，避免与普通代写/服务订单混在一起；辅导类订单由教务老师在辅导系统中登记。

2.2 登录与总管理员

  • 登录方式：所有用户通过「用户名 + 密码」登录；系统内置总管理员账号 Admin，默认密码 dan8008（首次登录后应强制修改）。
  • 总管理员权限：可新增/修改/删除系统用户并设置登录密码；可管理、修改、删除辅导套餐与流水；可查看权限说明。
  • 权限说明可见性：权限说明页面/入口仅对总管理员可见，其他角色登录后不应在导航中出现。

3. 功能模块

A. 辅导套餐总览

表格展示客户、顾问、第一次充值、最近上课、累计充值课时、累计上课课时、剩余课时、状态、明细入口、Tag。

B. 充值登记

按客户/订单录入充值课时数（必填）、充值金额（选填，可为 0）、日期、Course Code、Order Name、备注；红色字体显示充值课时数。

C. 上课明细登记

录入日期、上课老师、课时数（最小单位分钟，可自动换算）、本次费用、Course Code、上课 Link、备注；老师 Rate 为固定值，维护在老师档案中，选择老师后自动带出。

D. 财务联动

充值生成收入同步；上课生成支出待办；财务确认支出后上课明细锁定、不可编辑。

E. 订单过滤（派单系统）

派单系统订单列表默认过滤 order_type = tutoring；教务老师视角仅展示辅导订单。

F. 搜索与筛选

按顾问、客户、Course Code、Order Name、老师、日期区间筛选；支持组合查询。

G. 总管理员系统

用户 CRUD（设置登录密码）、辅导套餐/流水的修改与删除、权限说明查看。仅 Admin 角色可见。

5.3 锁定与状态规则

  • 未确认：上课明细 finance_status = pending，具有编辑权限的角色可修改、删除。
  • 已确认：财务支出确认后 finance_status = confirmed，locked = true，前端表单置灰，后端拒绝更新/删除。
  • 纠错：已锁定记录需要走“冲正/退款”流程，新增一条负数或调整流水，而不是直接修改原记录。
  • 套餐状态自动判断：剩余课时 = 0 时自动置为“结束”；剩余课时 > 0 且有上课记录置为“上课中”；剩余课时 > 0 且无上课记录置为“未约课”。

6. 财务系统联动接口

事件调用方向接口/消息关键字段
充值登记 辅导系统 → 财务系统 POST /finance/income customer_id, amount, package_id, transaction_id, type=tutoring_recharge
上课登记 辅导系统 → 财务系统 POST /finance/expense-todo teacher_id, amount, package_id, transaction_id, due_date
财务确认支出 财务系统 → 辅导系统 POST /tutoring/confirm-expense 或 Webhook transaction_id, status=confirmed, confirmed_by, confirmed_at
财务驳回/撤销 财务系统 → 辅导系统 POST /tutoring/reverse-expense transaction_id, reason, 解除锁定或生成冲正

幂等性：所有跨系统调用携带 idempotency_key，基于 transaction_id 去重，避免网络抖动导致重复记账。

无标准接口文档的对接策略：财务系统暂无标准接口，建议先与财务方约定最小契约（上述四类事件 + 关键字段），可选两种落地方案：① 辅导系统主动推送 + 财务系统提供回调 Webhook；② 若财务系统不支持回调，辅导系统按 transaction_id 轮询确认结果。建议以消息队列 + 幂等表保证最终一致性。

7. UI 关键界面

  • 登录页：参考 Orderlist 风格：居中白色卡片，顶部欢迎标题，用户名/密码输入框（带图标），绿色 Login 按钮，校验后进入系统。
  • 辅导套餐总览页：表格字段见截图 1：学校、第一次充值、最近上课、客户、顾问、累计充值、累计上课、剩余课时、状态、明细、Tag。支持按客户/顾问/日期筛选。
  • 明细页：展示单个套餐下所有 Transaction。同一行要么是充值（充值金额 + 课时数为正，红色字体），要么是上课记录（上课老师 + 课时数为负/消耗）。底部汇总：总课时数、总费用。
  • 新增流水弹窗：二选一模式：选择“充值”则显示充值金额、课时数；选择“上课”则显示老师、课时数、Rate、本次费用自动计算。Course Code、Order Name/上课 Link、备注共用。
  • 财务待办页（财务角色）：列出所有 finance_status=pending 的上课支出，支持批量确认。
  • 总管理员页：用户管理（新增/编辑/删除/设密码）、数据管理（套餐与流水修改/删除）、权限说明矩阵。仅 Admin 可见。

9. 已确认决策

  • 充值金额为选填项，可为 0；充值课时数为必填。
  • 上课老师 Rate 为固定值，维护在老师档案中，选择老师后自动带出，无需每次手填。
  • 财务系统暂无标准接口文档，需与财务方约定最小契约，采用 Webhook 回调或轮询确认。
  • “结束”状态由系统自动判断：剩余课时 = 0 即自动结束。
  • 仍可细化：老师档案维护入口、财务确认页字段、派单系统过滤实现层级（前端/后端）等。
本设计基于 2026-08-19 需求沟通整理，后续可依据确认事项细化数据库字段与接口契约。
